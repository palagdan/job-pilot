## Web Push

- **Env (api + worker):** `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`. Generate a pair with `pnpm push:keys`. Empty keys mean push is off: `GET /v1/push/vapid-key` returns 404 and the worker skips sending.
- **api:** `GET /v1/push/vapid-key`, `POST` / `DELETE /v1/push/subscriptions`.
  - Upsert is by endpoint. If another account signs in on the same browser, the subscription moves to that account. At most 10 live subscriptions per user.
  - Rate limit `push`: 20 per 10 min.
- **Worker:** new job `push.pack-ready {pipelineItemId}`.
  - **I added the enqueue to your `prepare-pack.ts`**, right after "pack.prepare done". `queue` is an optional dep, so your test still compiles; a failed enqueue only logs a warning.
  - The handler sends only if the item is still `ready_to_send`, the user isn't paused, and `schedule.notify_push` is on.
  - Push services answering 404/410 mark the subscription `failed_at`. The job retries only when no device was reached, so a device never gets the same push twice.
- **Web:**
  - `public/sw.js` handles push and notification clicks; a click opens `/review/:id`.
  - `lib/push/web-push.ts`: `enablePush`, `disablePush`, `syncPushSubscription`.
  - The Push toggle in the schedule form now subscribes for real. Each failure (denied, unsupported, not configured, other) reverts the toggle with its own message.
  - The app shell re-sends an existing subscription on start, to keep the endpoint current. It never prompts.

## Follow-ups in Pipeline

- **Contract:** `PipelineItem.followUp` = `{ id, sequence, dueAt, due }`, the next pending follow-up. The Pipeline endpoints fill it; your Today and Review mappers set it to `null`, which is a one-line change in each of your files.
- **`POST /v1/follow-ups/:id/done`: your version is kept** (merged from `feat/follow-ups`). I had built one too, with the same rule (#2 at +7 days), but yours has undo, so I removed mine.
  - The Pipeline "Mark follow-up as sent" calls yours and shows a toast with Undo.
  - No rate limit on it yet. My `pipelineWrite` limit needs `rateLimitStore` in your `ReviewDeps` if you want it there.
- **Pipeline UI:**
  - A due follow-up shows a "Follow-up due" / "Second follow-up due" badge and sorts first.
  - The row menu has **Open follow-up**, which goes to Review (please show the follow-up text there), and **Mark follow-up as sent**.
