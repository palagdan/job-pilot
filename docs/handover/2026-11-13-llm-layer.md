## Featherless facts the design is built on

Researched 2026-11-13 from featherless.ai/docs.

- OpenAI-compatible API at `https://api.featherless.ai/v1`. We use the official `openai` SDK (7.55) with a different `baseURL`.
- **Concurrency is the limit, not tokens.** Each in-flight request reserves "units" by model size: ≤16B = 1, 17–35B = 2, >35B = 4. Going over the plan budget returns **429**, and so does switching models too often. The docs say not to retry in a tight loop.
- 503 = no capacity (retry later). 400 = bad param, token limit or a **cold model** (we don't retry). 401/403 = key or gated model.
- JSON: only `response_format: { type: 'json_object' }`. No `json_schema` or guided decoding, so we validate with zod ourselves.
- Responses include token usage (also the final chunk when streaming). On a subscription there is no per-call cost, so **tokens are our cost proxy**.
- Qwen3 models can emit `<think>…</think>` reasoning. We turn it off (`chat_template_kwargs.enable_thinking = false`) and strip it from output anyway.

## What's in the branch

### `packages/llm`

| File | What |
| --- | --- |
| `client.ts` | `createLlm(config)` → `generateText`, `generateObject`, `streamText`. |
| `models.ts` | Model per task (`parse_cv`, `suggest`, `rank`, `write_cv`, `write_drafts`, `chat`) with units, max tokens, temperature. First guesses: Qwen3-14B (1 unit) for parse/suggest/rank, Qwen3-32B (2 units) for writing and chat. Final choice comes from the model spike. Override per task with `LLM_MODEL_<TASK>` / `LLM_UNITS_<TASK>`. |
| `semaphore.ts` | Weighted FIFO semaphore over concurrency units, so we queue locally instead of hitting 429. |
| `errors.ts` | `LlmError` with `code` (`rate_limited`, `unavailable`, `timeout`, `bad_request`, `auth`, `invalid_output`, `unknown`) and `retryable`. |
| `prompt.ts` | `definePrompt({ name, version, task, system, user })`. One file per prompt in `src/prompts/`. Bump `version` on every wording change; it is logged to `llm_usage.prompt_version`. |
| `usage.ts` | `createDbUsageRecorder(db)` writes one `llm_usage` row per HTTP attempt (task, model, prompt version, user, run, tokens, duration, succeeded). |
| `from-env.ts` | `createLlmFromEnv(env, { recordUsage })`. |

How a call behaves:

- **Retries:** 429, 503, 5xx, timeouts and connection errors retry up to 3 times with exponential backoff plus jitter (2 s base for 429/503, capped at 30 s; honours `retry-after`). The semaphore is released before sleeping. Other errors throw immediately.
- **`generateObject(schema)`:** puts the zod schema as JSON Schema into the system prompt, asks for `json_object`, strips `<think>` and ```` ```json ```` fences, and validates. If that fails, it makes **one repair attempt**, sending the model its output plus the validation errors. A second failure throws `invalid_output` with the raw output.
- **`streamText`** (for chat): yields text deltas with thinking removed. The semaphore is held until the stream ends, fails or the consumer stops early. Tool calling is not in yet; it comes with the chat task.
- Recording usage can never fail a call; errors are only logged.

Usage example (your suggestions endpoint):

```ts
const llm = createLlmFromEnv(env, { recordUsage: createDbUsageRecorder(db) });
const { object } = await llm.generateObject({
  task: 'suggest',
  prompt: suggestRoles, // definePrompt(...) in packages/llm/src/prompts/suggest-roles.ts
  userId,
  schema: z.object({ roles: z.array(z.string()).max(10) }),
  messages: suggestRoles.messages({ cvText }),
});
```

## Tested

- 16 unit tests with a fake OpenAI client:
  - semaphore: capacity, FIFO, abort
  - `generateObject`: valid, fenced/think-wrapped, repaired, fails twice
  - retries: 429 → success, 401 no retry, semaphore always released
  - `streamText`: think tags split across chunks, usage from the final chunk, early stop releases
- **Live against Featherless (passed):**
  - `generateObject` on Qwen3-14B returned schema-valid JSON.
  - `generateText` on Qwen3-32B: 28 in / 39 out tokens, 3.5 s.
  - `streamText` on Qwen3-32B: 1.7 s, no `<think>` text, usage captured from the final chunk.
  - The live test runs whenever `FEATHERLESS_API_KEY` is in `.env`.
- **Our account:** `GET /account/concurrency` → **limit 100 units**. Models are also priced per token on this plan, so tokens in `llm_usage` are real money.

## Needs your sign-off

1. **Concurrency budget split.** The limit is per process. api + worker together must stay within the plan budget, so set `LLM_CONCURRENCY_UNITS` per process. Our account has 100 units. Default is 4 per process (safe for local dev); in production e.g. api 20, worker 60, leaving headroom for local dev on the same key. The chat stream runs in the api, everything else in the worker.
2. **Suggestions via LLM** use task `suggest` with the cheap model. If you'd rather start with static lists only, that's fine.

## Gotchas

- Don't add many different models: Featherless also returns 429 when switching models too often. Keep to 2–3 models in total.
- A cold model can answer **400**, which we don't retry. If it shows up in practice, I'll add a targeted retry.
- `chat_template_kwargs` is sent as an extra body key (SDK 7.55 has no `extra_body`). Don't remove the cast in `client.ts`.
