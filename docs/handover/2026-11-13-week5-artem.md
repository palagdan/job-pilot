## api (`/v1/pipeline`, `application/pipeline/pipeline-use-cases.ts`)

- **`GET /v1/pipeline`:** status group AND type filters; sorts `next_follow_up` (default), `newest`, `status` (workflow order) and `company` (A–Z, case-insensitive).
  - `next_follow_up` sorts by the next thing that happens: the follow-up due date, else the interview (status `interview`), else the event start (status `registered`). Items with none come last.
  - The cursor is an offset (`"50"`); `limit` defaults to 50.
- **`GET /v1/pipeline/:id`** is the one to use from Review. It returns the same `PipelineItem` with **`nextStep`** and **`specialCvId`** filled (Today's `pursue` still returns them as null, see below).
- **`nextStep`** (the "Next follow-up" column) is set by status, with dates in the user's time zone:

  | Status | `nextStep` |
  | --- | --- |
  | preparing | "Preparing your pack" |
  | ready_to_send (job) | "Send it yourself" |
  | ready_to_send (event) | "Register yourself" |
  | failed | "Pack failed - try again" |
  | sent | "Follow up on 18 Nov", or "Follow-up due" once the date has passed |
  | registered | the event time, e.g. "Thu 19 Nov, 18:00" |
  | replied | "Reply to them" |
  | interview | the interview time |
  | offer | "Decide on the offer" |
  | no_reply | "Try another route" |

- **`PUT /:id/status`** (replied / interview + optional `interviewAt` / offer / rejected):
  - Jobs only, and only once sent (from `sent`, `replied`, `interview`, `offer`, `no_reply` or `rejected`). Anything else returns 409.
  - **Cancels pending `follow_up` rows** and clears `next_follow_up_at`. Your follow-up job should skip cancelled rows.
- **`PUT /:id/route`:**
  - Only before sending (`preparing`, `ready_to_send` or `failed`), using the same per-type rule as your Today route options.
  - It sets the status back to **`preparing`**, mirrors the route onto `opportunity.route`, and **enqueues `pack.prepare` again**. Your handler must handle a re-run: replace the drafts and the special CV for the item.
- **`POST /:id/stop`** (C06): sets Skipped and cancels follow-ups. It's idempotent.
- **Notes:** `GET` / `POST /:id/notes` (newest first, at most 2000 characters).
- Every status or route change writes an `activity` row (`pipeline.status`, `pipeline.change_route`, `pipeline.stop`). None are undoable; the contract has no undo token.
- **Your pack endpoints** (`/:id/drafts`, `/sent`, `/not-sent`, `/registered`, `/retry`, `/event.ics`):
  - They aren't on my router yet. Add them to `http/routes/pipeline-routes.ts`, or mount your own Hono router on `/pipeline` **after** mine.
  - `/stats` is registered before `/:id`, so it won't collide.
