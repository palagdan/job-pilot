# Handover: agent run, prefilter + ranking (M3, Daniil)

**From:** Daniil · **To:** Artem · **Date:** 2026-11-13

The `agent.run { runId }` job now fills `opportunity` with ranked jobs and events for a user, which is the data for Today.

## How it works

- **Prefilter (SQL, `apps/worker/src/agent/prefilter.ts`):**
  - **Eligible jobs:** not expired, seen within 21 days, and not already shown to this user.
  - **Role match:** keywords from the target roles + the top 8 skills, plus Czech equivalents (developer → vývojář, …), matched with ILIKE on the title or description.
  - **Location:** the job's city matches a target city (Prague = Praha), OR the city is unknown (many Jobs.cz rows), OR it's remote when the user wants remote.
  - **Exclusions:** the company or title matches an exclusion → dropped.
  - Title matches come first, then the newest. The cap is `AGENT_MAX_CANDIDATES` (25). If fewer than 5 match, recent local jobs fill up to 5.
  - **Events:** upcoming within 45 days, in a target city or online, limit 10.
- **Ranking (`agent/rank.ts`):** `rank-job@2` (Qwen3-32B) per job and `rank-event@1` per event, run in parallel; one failure is skipped.
- **Handler:**
  - Claims a `queued` run atomically and writes the 4 steps.
  - Inserts opportunities with route `direct` (jobs) or `event` (events), a route reason, and feed status `new`.
  - Sets `candidatesCount`, `newCount` (fit ≥ 50) and `schedule.last_run_at`. A missing profile or targets → `failed` with an error.
- **Dev command:** `pnpm --filter @job-pilot/worker agent:run <email>` queues a manual run (prints "agent is busy" if one is active).

## Live results (132 real jobs)

- **Developer profile:** 12 candidates, 5 with fit ≥ 50, in 27 s. #1 was Senior full-stack developer (Product Fruits) at **88**; DevOps and product roles ranked mid; sales and helpdesk scored ~10.
- **Demo user (marketing leadership targets):** 15 candidates, 1 with fit ≥ 50, in 23 s. The DB simply has few marketing leadership jobs.
- **Prompt fix:** `rank-job@2` makes low scores name the mismatch instead of "Matches your skills…", and only uses "excluded" for real exclusions (v1 did both wrong).

## Known gaps

- Unknown-city Jobs.cz rows are kept, so some candidates may be outside Prague.
- Remote jobs abroad (e.g. Bratislava) pass the remote rule.
- Agency exclusions ("No agencies") are judged by the LLM, not by SQL.
