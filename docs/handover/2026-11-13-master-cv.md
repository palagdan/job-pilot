# Handover: master CV generation (M2, Daniil)

**From:** Daniil · **To:** Artem · **Date:** 2026-11-13

The worker now handles `cv.generate-master { userId, uploadId? }`, which your `completeOnboarding` (and later regenerate) enqueues.

## What it does

- **Inputs:** the parsed upload (`uploadId`, else the latest parsed one), the confirmed profile, proofs, targets and schedule.
- **Versions:** a new master `cv` row each run (`version` = max + 1, origin `generated`), Generating → **Needs review**. A row still `generating` is reused on retry, so no extra version is created.
- **Prompt:** `write-master-cv@1` on DeepSeek-V3.2 (`write_cv`), returning `{ cv: CvContent, changes: string[] }`. It rewrites for the target roles using only facts from the inputs, keeps the CV language, and the profile overrides the original. `changes` holds 3–6 user-facing "What changed" items.
- **Failure:** status `failed` and `error` = `messages.masterCvFailed` ("We could not write your CV. Use your original CV or try again.", E05). Not retried.
- **Email:** after success, if onboarding is complete, `email.send` `agent_live` is enqueued (dedupe `agent_live:<userId>`). Email **03 "Your JobPilot agent is live"** links to `${WEB_URL}/cvs/new` and summarises: looking for, where, runs, notifies by. It respects `notify_email`.

## For your screens (06 New CV, 09 CVs)

- Read the latest master: `content` (render PDF/DOCX from it), `changes` ("What changed"), `status`, `error`.
- Confirming (C02) and superseding older versions are your endpoints; the job never touches `confirmed_at` / `superseded_at`.
